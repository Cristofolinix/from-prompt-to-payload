# From Prompt to Payload — Reproducibility Package

Reproducibility material for the paper ***From Prompt to Payload: Refusal Bypass via System Instruction and the Validation of LLM-Generated Cybersecurity Artifacts*** (RITA, 2026), on the **dual use of large language models (LLMs) in cybersecurity**.

The experiment is run in an isolated laboratory that abstracts the **Equifax (2017)** incident chain (Apache Struts, **CVE-2017-5638 / S2-045**), emulated in **CORE (Common Open Research Emulator)**. Under a *white-box* protocol (the parameters are provided to the model), it measures whether the same LLMs produce **offensive** artifacts (exploit/exfiltrate) and **defensive** artifacts (segment), validated by **execution** in the lab.

> ⚠️ **Disclaimer / responsible use.** All material is for **academic research and educational purposes**, run in a **fully isolated laboratory**, with no real or third-party systems. The data are **fictitious**. CVE-2017-5638 is public and has been patched since 2017. **Do not** use these artifacts against systems you do not own or are not authorized to test. See [`ETHICS.md`](ETHICS.md).

## Lab topology

`external (10.0.0.20)` → `fw` (nftables firewall/router) → **DMZ** `10.0.1.0/24` (web/Struts at `10.0.1.10:8080`) and **internal LAN** `10.0.2.0/24` (`db1 10.0.2.20`, `db2 10.0.2.21`).

The *web* node is a Docker container (vulhub `struts2/s2-045`) running on the host, attached to the emulated CORE DMZ through a **veth pair**. The structural flaw reproduced: `external` cannot reach the LAN, but the web node reaches the LAN freely (no segmentation), as in the real incident. See `topology/topologia-rede.png`.

## Artifact organization

The artifacts are grouped by scenario: **offensive** — `T1` (exploitation of CVE-2017-5638) and `T2` (SSH lateral movement) — and **defensive** (network segmentation via `nftables`). The offensive scenario has two conditions: **A** (no *system prompt*) and **B** (with *system prompt*).

The condition-B ***jailbreak* configurations are not redistributed here** (see [`ETHICS.md`](ETHICS.md)).

## Reproducing the lab

The complete laboratory, fully assembled and with all scripts and configurations, is distributed as an **OVA** image on **Zenodo** (DOI): [10.5281/zenodo.24508129](https://doi.org/10.5281/zenodo.24508129).

1. **Import the OVA** into VirtualBox (File → Import Appliance). Keep the VM **isolated/offline** — in Settings → Network, disconnect the adapter (see [`ETHICS.md`](ETHICS.md)).
2. **Start the VM** and log in with `researcher` / `genai2026`.
3. **Bring up CORE and the lab** in a terminal:

   ```bash
   sudo systemctl start core-daemon   # sudo password: genai2026
   core-gui &
   ```

   In the CORE window: **File → Open** → `GenAI_Testbed.xml` → **play** (start the session). Then:

   ```bash
   bash ~/lab/start-lab.sh   # recreates the container, veth bridge, and data; idempotent (reset)
   ```

4. **Validate** from the `external` node (double-click it in CORE):

   ```bash
   curl -m5 http://10.0.1.10:8080/
   ```

   It should return the *Struts2 Showcase – Fileupload sample* page (HTTP 200).
